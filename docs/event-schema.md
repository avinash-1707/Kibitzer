# Kibitzer — Event Schema

Every adapter's only contract with the rest of the system is: translate whatever the
native tool gives you into this shape and POST it to `/events`. Nothing downstream should
ever branch on which CLI produced an event, except for display purposes (e.g. showing a
small tool-source badge).

> Field names below are verified against current (Aug 2026) sources: Claude Code hooks
> reference (`docs.claude.com/en/docs/claude-code/hooks`), OpenCode plugin source
> (`anomalyco/opencode`, `@opencode-ai/plugin@1.18.25`), and OpenAI Codex source
> (`openai/codex`). Where an adapter's raw payload uses different casing (kebab-case for
> Codex, snake_case for Claude Code), the adapter is responsible for mapping into the
> camelCase canonical shape below.

## Canonical event

```ts
// packages/shared/src/event.ts — imported by server AND adapters
export type EventSource = "claude-code" | "opencode" | "codex";

export type EventType =
  | "session_start"
  | "session_end"
  | "tool_call"        // a single tool invocation (Bash, Edit, Write, Read, ...)
  | "turn_complete"    // agent finished a full turn (Codex's only reliable granularity)
  | "file_edit"        // a file was created/modified/deleted
  | "checkpoint";      // manual "hey narrator, log this" — post-MVP; no producer wired yet

export type Outcome = "success" | "failure" | "unknown";

export interface KibitzerEventDetail {
  tool?: string;            // e.g. "Bash", "Edit", "Write"
  command?: string;         // for Bash-type calls, the literal command (redact secrets)
  filePath?: string;
  outcome?: Outcome;
  isDestructive?: boolean;  // set by the SERVER's classifier (pipeline step 0), never the model
  message?: string;         // last_assistant_message on turn/session end; user text on checkpoint
  raw?: unknown;            // original native payload, kept for debugging, never shown in UI
}

export interface KibitzerEvent {
  id: string;               // uuid v4, generated by the adapter (crypto.randomUUID())
  sessionId: string;        // stable per build session (see per-adapter mapping)
  source: EventSource;
  type: EventType;
  timestamp: string;        // ISO 8601 (new Date().toISOString())
  detail: KibitzerEventDetail;
}
```

The POST body to `/events` is exactly one `KibitzerEvent`. Adapters own ID/timestamp
generation. The server validates the shape (a small zod schema, see `architecture.md`),
rejects malformed bodies with `400`, then sets `detail.isDestructive` itself in pipeline
step 0 (adapters can't import the classifier — see below). Everything else is passed through
untouched.

## Adapter mapping — Claude Code (primary, richest signal)

**Mechanism:** native `type: "http"` hooks in `.claude/settings.json`. Claude Code POSTs
the hook payload directly to a URL — no shell script needed. Use `async: true` so hooks
never add latency to a tool call, and rely on the server always returning fast `2xx`
(Claude Code fails open on any hook error, so a down Kibitzer never degrades the session).

Because the native HTTP hook posts Claude Code's *own* payload shape (not ours), Kibitzer
exposes a **thin translation endpoint per source** rather than making the CLI match our
schema. Claude Code hooks POST to `/ingest/claude-code`, which normalizes and forwards into
the same internal pipeline as `/events`. (`/events` remains the canonical shape for the
OpenCode and Codex adapters, which run our code and can emit it directly.)

`.claude/settings.json` (committed to the demo repo):

```json
{
  "hooks": {
    "SessionStart": [
      { "matcher": "", "hooks": [
        { "type": "http", "url": "http://localhost:8787/ingest/claude-code", "timeout": 5 }
      ]}
    ],
    "PostToolUse": [
      { "matcher": "Bash|Edit|Write|Read", "hooks": [
        { "type": "http", "url": "http://localhost:8787/ingest/claude-code", "timeout": 5, "async": true }
      ]}
    ],
    "PostToolUseFailure": [
      { "matcher": "Bash|Edit|Write", "hooks": [
        { "type": "http", "url": "http://localhost:8787/ingest/claude-code", "timeout": 5, "async": true }
      ]}
    ],
    "Stop": [
      { "matcher": "", "hooks": [
        { "type": "http", "url": "http://localhost:8787/ingest/claude-code", "timeout": 5 }
      ]}
    ],
    "StopFailure": [
      { "matcher": "", "hooks": [
        { "type": "http", "url": "http://localhost:8787/ingest/claude-code", "timeout": 5 }
      ]}
    ],
    "SessionEnd": [
      { "matcher": "", "hooks": [
        { "type": "http", "url": "http://localhost:8787/ingest/claude-code", "timeout": 5 }
      ]}
    ]
  }
}
```

> The URL hardcodes `:8787`; native HTTP hooks can't read `KIBITZER_PORT`. If you change the
> server port, update this file too. (This is the one adapter that can't be env-driven.)

> `Bash|Edit|Write|Read` comma/pipe matcher lists require Claude Code v2.1.191+. If the demo
> machine is older, fall back to `"matcher": ""` (match all) and let the server's debounce
> drop the noise.

Raw Claude Code hook payload → canonical (done in `/ingest/claude-code`):

| Claude Code field (stdin/HTTP body) | Canonical field | Notes |
|---|---|---|
| `session_id` | `sessionId` | stable across the whole session |
| `hook_event_name` | drives `type` mapping | see below |
| `tool_name` | `detail.tool` | "Bash", "Edit", "Write", "Read" |
| `tool_input.command` | `detail.command` | Bash only |
| `tool_input.file_path` | `detail.filePath` | Edit/Write |
| `last_assistant_message` (Stop) | `detail.message` | reliable final text; `transcript_path` may lag |

**`outcome` is derived from `hook_event_name`, not from `tool_response`** — `PostToolUse`
fires *only* on success and `PostToolUseFailure` *only* on failure, so the event name is the
authoritative signal (a `tool_response.success` field would be redundant and, on
`PostToolUse`, always true).

`hook_event_name` → `type` (+ `outcome`):
| Hook event | `type` | `outcome` |
|---|---|---|
| `SessionStart` | `session_start` | — |
| `PostToolUse` | `tool_call` | `success` |
| `PostToolUseFailure` | `tool_call` | `failure` |
| `Stop` | `turn_complete` | `success` |
| `StopFailure` | `turn_complete` | `failure` |
| `SessionEnd` | `session_end` | — |

> `SessionEnd` fires on CLI exit and won't happen mid-demo — the devpost is generated by the
> dashboard's explicit "Wrap up session" button (`POST /session/:id/end`), not by this event.
> Optionally wire `StopFailure` for the `turn_complete`+`failure` drama beat.

## Adapter mapping — OpenCode (stretch #1)

**Mechanism:** a plugin file at `.opencode/plugins/kibitzer.ts` (directory is **plural**).
Plugins run under Bun, so bare `fetch` is available. `session.idle` is **deprecated** —
prefer `session.status` with `status.type === "idle"`.

```ts
// .opencode/plugins/kibitzer.ts
import type { Plugin } from "@opencode-ai/plugin"; // @opencode-ai/plugin@1.18.25

const ENDPOINT = process.env.KIBITZER_ENDPOINT ?? "http://localhost:8787/events";

// file.edited carries no session id, so track the latest one seen on tool/session events.
let currentSessionId = "unknown";

function mk(sessionId: string, type: string, detail: Record<string, unknown> = {}) {
  return {
    id: crypto.randomUUID(),
    sessionId,
    source: "opencode",
    type,
    timestamp: new Date().toISOString(),
    detail,
  };
}

async function emit(body: unknown) {
  try {
    await fetch(ENDPOINT, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(body),
      signal: AbortSignal.timeout(3000),
    });
  } catch {
    /* collector down — never block the agent */
  }
}

export const Kibitzer: Plugin = async () => ({
  "tool.execute.after": async (input, output) => {
    // input: { tool, sessionID, callID, args }; output: { title, output, metadata }
    currentSessionId = input.sessionID;
    await emit(mk(input.sessionID, "tool_call", {
      tool: input.tool,
      command: input.args?.command,
      filePath: input.args?.filePath ?? input.args?.file_path,
      outcome: "success", // reaching `.after` implies the tool ran
      raw: { args: input.args, output: output.output },
    }));
  },
  event: async ({ event }) => {
    if (event.type === "session.created") {
      currentSessionId = event.properties.info.id;
      await emit(mk(currentSessionId, "session_start"));
    } else if (event.type === "session.status" && event.properties.status?.type === "idle") {
      // per-TURN idle → turn_complete (NOT session_end; the session isn't over)
      await emit(mk(event.properties.sessionID, "turn_complete", { outcome: "success" }));
    } else if (event.type === "file.edited" && currentSessionId !== "unknown") {
      await emit(mk(currentSessionId, "file_edit", { filePath: event.properties.file }));
    }
  },
});
```

| OpenCode source | Canonical | Notes |
|---|---|---|
| `tool.execute.after` `input.tool` | `detail.tool` | result string is `output.output`, **not** `output.result` |
| `input.sessionID` | `sessionId` | present on tool + `session.status`; cached for `file.edited` |
| `event: session.created` `properties.info.id` | `sessionId` (session_start) | id nested under `info` here |
| `event: session.status` `status.type==="idle"` | `turn_complete` | per-turn, not end-of-session — successor to deprecated `session.idle` |
| `event: file.edited` `properties.file` | `detail.filePath` | string path; attributed to the cached `currentSessionId` |

> OpenCode has no reliable "whole session finished" signal for a demo (idle is per-turn), so
> the devpost is triggered by the dashboard's explicit "Wrap up session" button, not by any
> OpenCode event. Same for Codex.

## Adapter mapping — Codex (stretch #3, coarsest)

**Mechanism, updated:** the legacy `notify` key still works but is explicitly marked for
removal in Codex source. The forward-compatible path is the **`Stop` hook** (stdin JSON,
same `turn_id` + `last_assistant_message`), with `PostToolUse` available if per-tool detail
is ever wanted. For a one-day build, `notify` is the smaller surface and needs no `/hooks`
trust review — use it, but note the deprecation in the doc/demo.

`notify` delivers its JSON as the **last argv argument** (not stdin), in **kebab-case**,
and Codex discards the process's stdout/stderr and does not await it.

```toml
# ~/.codex/config.toml  (user-level ONLY — ignored if placed in a project .codex/config.toml)
notify = ["/usr/bin/env", "node", "/abs/path/to/kibitzer/adapters/codex/notify.js"]
```

```js
// adapters/codex/notify.js
const raw = process.argv[process.argv.length - 1]; // payload is the LAST argv element
let e; try { e = JSON.parse(raw); } catch { process.exit(0); }
if (e.type !== "agent-turn-complete") process.exit(0);

fetch(process.env.KIBITZER_ENDPOINT ?? "http://localhost:8787/events", {
  method: "POST",
  headers: { "content-type": "application/json" },
  body: JSON.stringify({
    id: crypto.randomUUID(),
    sessionId: e["thread-id"],
    source: "codex",
    type: "turn_complete",
    timestamp: new Date().toISOString(),
    detail: {
      outcome: e["last-assistant-message"] ? "success" : "unknown",
      message: e["last-assistant-message"] ?? undefined,
      raw: e,
    },
  }),
}).catch(() => {}).finally(() => process.exit(0));
```

| Codex `notify` field | Canonical | Notes |
|---|---|---|
| `type: "agent-turn-complete"` | `type: "turn_complete"` | the only event `notify` fires |
| `thread-id` | `sessionId` | Codex thread/session id |
| `turn-id` | `detail.raw` | kept for debugging |
| `last-assistant-message` | `detail.message` | can be `null` |
| `input-messages` | `detail.raw` | user text that started the turn |

## Destructive-command classifier (shared helper)

One pure function, used by the **server's pipeline** (step 0) as the source of truth. The
adapters run inside *other* repos and can't import `packages/shared`, so they simply omit
`isDestructive` and let the server classify — adapters never need this file. Kept pure so
it's unit-testable:

```ts
// packages/shared/src/classify.ts
const DESTRUCTIVE = [
  /\brm\s+-rf\b/,
  /\bgit\s+push\s+.*--force\b/, /\bgit\s+push\s+-f\b/,
  /\bgit\s+reset\s+--hard\b/,
  // SQL only inside a db invocation, so "commit -m 'truncate log'" doesn't false-positive.
  /\b(sqlite3|psql|mysql)\b[^|;]*\b(DROP\s+TABLE|TRUNCATE)\b/i,
  /(^|\s)(>>?|tee|cat)\s+\S*\.env(\.|$|\s)/,   // writing/reading .env via redirect/tee/cat
];

export function isDestructive(detail: { command?: string; filePath?: string }): boolean {
  const cmd = detail.command ?? "";
  if (DESTRUCTIVE.some((re) => re.test(cmd))) return true;
  if (detail.filePath && /(^|\/)\.env(\.|$)/.test(detail.filePath)) return true;
  return false;
}
```

This flag feeds the drama meter directly — see `persona-prompts.md`.

## Debounce rule (processing pipeline, not adapters)

Adapters send everything; filtering is the backend's job so the raw log stays complete for
analytics even when a narration line is skipped. **Skip narration (but still store) for:**
- `Read`-type `tool_call`s, and
- any event within 2s of an identical `type`+`detail.tool` pair (collapses a burst of the
  same action into one narrated line).

Implemented as a pure predicate `shouldNarrate(event, recentEvents)` so it's unit-testable
(see `architecture.md` §4).
